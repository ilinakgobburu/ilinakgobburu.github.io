Finding MEV bots in Ethereum token transfers

MEV (maximal extractable value) bots are automated traders that profit from the order of transactions in a block, often by paying high gas fees to go first. Only 0.04% of addresses carry an MEV label, so this project asks how far behavior alone (gas, fees, value, who trades with whom) can go toward finding them. Five models come at it from different angles. One of them was tuned by an AI agent running Andrej Karpathy's autoresearch loop.

An AI agent ran the experiments: Karpathy's autoresearch, repurposed

The idea

In March 2026 Andrej Karpathy released autoresearch, a small repo built on one idea: give an AI agent a real training setup and let it experiment on its own overnight. The agent edits one file, runs a five-minute training job, keeps the change if the validation score improved, reverts it if not, and repeats. The researcher stops editing the Python. They write program.md, the agent's instructions, and read the log in the morning.

Karpathy aimed the loop at training a small language model. This project aimed the same loop at a different problem: ranking Ethereum transactions by how unusual they look, without ever showing the model which ones are MEV.

Why only one of the five models

The loop needs one honest number to climb. Anomaly ranking has one: how concentrated the known MEV transactions are at the top of the ranking. Clustering doesn't. Silhouette rewards tidy shapes, and steering clusters toward MEV would undo the point of working without labels.

Using a loop for the clustering half would produce a confident wrong answer.

What 19 experiments found

Lift at the top 5% takes the 5% of transactions the model calls most unusual and divides their MEV share by the MEV share overall (10.2% in the sample). A random ranking scores 1.0. A perfect one scores 9.82.

Lift at the top 5%, experiment by experiment4,731-transaction sample
Each dot is one experiment. Filled: kept, so the change became the new starting point. Hollow: reverted. The line is the best score so far.
What the loop learned
  • Pruning beat everything. Dropping features that carried no signal on their own (single-feature AUC below 0.51) took lift from 1.66 to 4.28 in one step, +158%. No other change gained more than 17%.
  • The baseline was worse than one column. All 18 features through an IsolationForest scored 1.12. Gas price alone scored 3.74. The problem was noise, not the model.
  • Other models lost. Local outlier factor 1.25, PCA reconstruction error 0.91, summed z-scores 2.45, a one-class SVM 3.45.
  • Tuning did nothing. More trees and fewer features per split scored lower. The contamination setting moves the decision threshold, not the ranking, so it can't change lift.
  • Returns diminished fast. The first three experiments took lift from 1.12 to 4.28. The next sixteen added one more point.

Five models, three units of analysis

The same data supports very different questions depending on what one row is: a transaction, an address, or a token. Labeled and label-free methods each cover a gap in the other.

Per transactionsupervised

Logistic regression

0.9717test ROC-AUC

Classifies each of 720,599 transactions from structure, fees, gas, timing and contract method, with SMOTENC to rebalance. PR-AUC 0.858. At a 0.82 threshold: precision 0.73, recall 0.82. Validation and test scores match, so it generalizes.

Per addresssupervised

Two-stage XGBoost

0.185MEV PR-AUC, vs 0.021 flat

Stage one separates MEV bots from everyone else; stage two sorts the rest into whales, trading bots and retail. Outgoing transfer count is the top signal (importance 0.63). It also flags 641 unlabeled addresses that behave like MEV bots.

0.651F1, verified tokens

Predicts whether a token is verified from how it trades, never its name or symbol. The strongest signal is how much of its flow goes to centralized exchanges.

Where the methods agree, and where they don't

  • Gas price is the shared MEV signature. The supervised model weights it positively. The DEX-arbitrage cluster's median gas price is 229 gwei. In the anomaly ranker's top 5%, transactions above 200 gwei are 93 times more common than in the rest (9.3% vs 0.1%).
  • Two sides of the same trade. The transaction-level models flag senders with ENS names; the bots the clustering finds have none. The MEV label marks a transaction if either side is a known bot, so the transaction models learn the people trading with bots, and the clustering finds the bots themselves.
  • Features beat models, in all five pipelines. Feature engineering and selection moved results more than the choice of algorithm.

Limits

  • Sample optimism. The anomaly ranker was tuned on 4,731 transactions. Lift fell from 5.28 to 3.17 at full scale; the full-scale number is the honest one.
  • No held-out set for the ranker. Normal for unsupervised ranking, but it limits claims about new data.
  • The label is a proxy. A transaction counts as MEV if either side is on a known bot list, which mixes bot-side and user-side activity.
  • Few MEV addresses. The address-level test set holds 22 of them; the two-stage model finds 8.
